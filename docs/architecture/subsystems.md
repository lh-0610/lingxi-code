## 子 Agent 并行 + worktree 隔离（src/subagent.py + worktree.py）
- `spawn_agents(tasks)` 把多个**相互独立**的子任务并行派给子 Agent，**各自在独立 git worktree 改代码**。仅明确 `completed` 且父子均未停止时自动合并；失败、未知、未验证、取消、超时均保留隔离区和原因。合并后父会话的相关验证结果失效。
- **固定合并身份**：创建时解析 `base_sha`，创建分支与最终净补丁使用同一 SHA；`project_path` 明确记录原始 checkout。元数据存入隔离区真实 Git admin 目录的 `lingxi-worktree.json`，不进入用户 diff。支持已有 linked worktree 作为项目，不从 common Git dir 猜目标。
- **恢复与兼容**：缺失/损坏元数据或身份变化时保留隔离区，拒绝自动恢复/合并，仍允许用户显式丢弃。旧版隔离区不猜基点自动迁移。`worktree.changed_files()` 使用临时 index 获取已提交、未提交和未跟踪净变化；读取失败不能伪装成没有改动。
- 子 Agent 是 `is_subagent=True` 的会话，`ui_ref=None`（不弹前台确认）；文件/命令严格限定在自己 worktree（`tools_common._subagent_path_rejection` / `_subagent_command_rejection` best-effort 沙箱）
- `worktree.py` 管隔离区生命周期；`Session.worktree` 路由该会话所有文件/命令落点（`_project_cwd` 优先返回 worktree）

## 只读探索子代理（src/tools_explore.py）
- `explore(question, thoroughness)`：主 Agent 把要翻好几个文件才弄得清的问题派出去，子代理在自己的上下文里搜、读，只交回带 `路径:行号` 的报告。七家主流 coding agent 都这么做；评测 011 里主循环挨个读文件要 60 轮
- 子会话 `is_subagent=True`、`worktree=项目根`（只能读项目里的文件），不建 worktree；三个会话级字段：`allowed_tools`（`resolve_bound_llm` 只绑这些、`_execute_tool` 再硬拦）、`max_rounds`（quick 8 / medium 20 / thorough 40）、`system_prompt_override`（`get_system_prompt` 直接返回它——streaming 每轮都会重渲染系统提示词）
- 跑满上限时多调一次模型（不带工具）把已查到的写成报告，而不是只交回"已达上限"；父任务停止时子代理跟着停
- 遥控只读模式不放行：子代理能读项目里任何文件，绕得过敏感文件黑名单

## 代码模式与代码地图（src/tools_code.py + repo_map.py）
- DeepSeek 一轮只调 1.2~1.6 个工具、批量工具给了也不用，这两样不靠它自觉
- `repo_map.build_task_map`：大项目（≥30 个源码文件，任何语言）里每条新消息开跑前，按任务里的词（IDF 加权，中文切 2~4 字）和引用图挑最多 12 个文件，列出类 / 函数和行号，放在系统提示词末尾（`session.task_map`）。最高分 <15（任务词在代码里对不上）时改给项目概览：压缩过的三层目录树 + PageRank 挑的核心文件；消息短于 6 字什么都不给
- 同一会话尽量不换地图（`agent._prepare_task_map`）：地图变了系统提示词就变，整段历史按未命中计费。新消息算不出地图（"继续"）留旧的；算出了不同的，只在对话 ≤ 8000 token 时换
- `code_graph.py`：A 文件里出现 B 文件定义的类 / 函数名就记 A→B（不解析 import，所有语言通用）；方法名权重 0.2、定义在 >6 个文件的名字不算、太弱的边丢掉。git 仓库按 `git ls-files` 列文件（跳过 .gitignore）
- `run_code`：模型写一小段 Python 调只读工具（`CODE_TOOL_NAMES`），一轮做完多次读 / 搜。写工具不进程序——执行前记录、改动确认、验证追踪、Plan 拦截都挂在普通工具那条路上

## 代码导航（src/lsp_client.py + codeintel.py + tools_codemap.py）
- `find_definition` / `find_references`：**LSP（最准，装了语言服务器）→ jedi（Python）→ 退回 search_files** 的降级链
- **LSP 多语言**：按文件扩展名选语言组（python / typescript〔含 js/jsx/tsx〕/ go / rust / cpp〔含 .c/.h〕/ java），每组一个常驻服务器单例（`_servers` dict，不再写死一个 pyright）。默认命令 pyright-langserver→pylsp、typescript-language-server、gopls、rust-analyzer、clangd、jdtls；`config.lsp_servers` 覆盖 python、`config.lsp_languages`（对象，值为命令字符串或候选列表）覆盖其它组。`didOpen` 的 `languageId` 也按扩展名给（tsx→typescriptreact、jsx→javascriptreact、.h→cpp），不再写死 `"python"`——这是旧版只支持 Python 的根因。jdtls 启动补 `-data <工作区>`，工作区**不在项目根里**（早先建 `<项目根>/.lingxi-jdtls-workspace` 会污染用户项目、被 git 看见）：按项目根 realpath 的 sha256 前 16 位 keyed 到 `get_data_dir()/lsp_workspaces/<hash>`，dev 期数据根恰是项目根时退回临时目录（`_jdtls_workspace`，best-effort，起不来就降级）。**Windows 上 npm 装的语言服务器（`.cmd` shim）裸名字起不来**：`_LspServer.__init__` 用 `shutil.which(argv[0])` 解析成完整路径再交给 CreateProcess（它只认 `.exe`、不查 PATHEXT，裸名字会 WinError 2）。认不出扩展名 → 不起服务器、`definition/references` 返回 None
- **jedi 只兜 Python**：LSP 没命中后，非 `.py/.pyw` 文件不再拿 jedi 硬解析（会得到误导性空结果），而是诚实提示"装对应语言服务器 / 用 search_files"（`_non_python_nav_hint`）
- `codeintel.py`：tree-sitter 符号提取 / 导入追踪，支撑 `code_map` / `related_files` / 代码地图。Python / JS / TS 用官方单语言包和专门遍历；其余语言用 tree-sitter-language-pack 0.x（语法预编译在 wheel 里；1.x 运行时联网下载，不用）+ 通用遍历（按节点类型名认定义）；没有语法库的退回通用正则。Vue / Svelte 只解析 `<script>`
- `related_files`：Python / JS / TS 按 import 语句；其余语言按引用图给"它用到的 / 用到它的"
- 这些都是只读工具，进 `PLAN_MODE_READONLY_TOOLS`、不弹确认

## 持久化（memory.py 并发安全）
- 所有读写 `chat_memory/` 的函数都被 `threading.RLock` 串行化（`save_session` / `_update_index` / `_write_session_title` / `load_session` / `list_sessions` / `delete_session` / `move_sessions_to_no_project` / `rename_session` / `_ensure_memory_dir`）。例外：`search_sessions` 只在读 index 时持锁，逐个读正文在锁外（见「会话重命名与跨会话搜索」）
- save_session 必须在同一临界区内取得 ID/标题/历史快照并写 session/index、rekey；只锁写盘会让 UI 的旧快照覆盖 worker 的新回复。
- 用 RLock 不用 Lock：`save_session` 自己持锁时还会调 `_update_index`（也持锁），普通 Lock 会自死锁
- 修复了原来"快速发两条消息时，标题生成线程和 save_session 同时改 index.json 互相覆盖丢会话"的并发 bug

## 会话历史保留与侧栏加载更多
- **索引全量保留，删除只能由用户发起**：`_update_index` 不做任何数量截断，新会话插最前、旧条目原地更新（刷新 `updated`）。早先索引截断到 `SESSION_HISTORY_LIMIT=50` 并把挤出名额的会话**正文一并删掉**——内存里还开着的靠注册表检查幸免，没打开的连正文带索引一起消失且无法恢复。`SESSION_HISTORY_LIMIT` 常量已废除：不要把"历史保留"和"界面展示数量"混为一谈。
- **展示数量是界面状态**（`limits.SIDEBAR_GROUP_VISIBLE_INITIAL/STEP`，各 30）：侧栏每个分组初始显示 30 条，组尾「显示更早的 N 条」按步长追加；每组按 `collapse_key`（项目路径 / 无项目 / RAG 专用键）**独立计数**——RAG 与编码"无项目"都以 project=None 渲染，计数与折叠共用同一套键区分，互不串用。计数是内存级（`_group_visible_counts`），普通刷新（重渲染）不重置；删除会话后剩余不足时按钮自然消失。
- **排序**：更新时间倒序，同刻按 id 倒序（id 含"年月日_时分秒_微秒"，跨重启稳定）。**只有对话内容变了的保存才刷新 `updated`**（`save_session_report` 比对正文 messages，没变就沿用旧值、`_update_index(touch=False)`；**比对去掉系统提示词**（`_conversation_only`）：切会话时它按当前代码重新生成，里面有「今天是 X 月 X 日」和工作目录，跨天或改过提示词后必然不同——算进去的话隔天点开任何会话都被顶到最前、显示「刚刚」，复发过一次），把有新活动的会话带回所在分组的近期位置。切会话前会先把当前会话存一遍——早先每次保存都刷新，看过一眼的会话就被顶到最前（用户实测：点谁谁跑到第一个），守它的是 `scripts/test_session_order_on_switch.py`。
- **正常保存永不触发历史清理**；用户主动删除（`delete_session`）连正文 + 索引条目 + 索引修复登记 + inflight sidecar 一起删，修复路径以正文为唯一真相（正文不在 → 销案不复活），已删除的会话不会因后续保存、索引修复或重启复活。不做孤儿 JSON 扫描重建索引——那会复活用户主动删除的会话，也不声称能恢复已被旧代码删除的数据。

## 对话时间轴：编辑 / 回退 / 分叉（src/memory.py + src/ui/timeline.py）
- 每条用户气泡下挂三个幽灵按钮（`MessageView.add_user_actions`，编辑/回退/分叉），点击发 `user_edit_requested / user_rewind_requested / user_fork_requested` 信号，参数是该消息在 `chat_history` 里的**绝对下标**。重绘（`_replay_history` 用 `enumerate`）和实时发送（`_do_send` 记下追加前的 `len`）两路都挂。
- 三个操作统一以「被点消息之前」为边界（`TimelineMixin`，src/ui/timeline.py）：**编辑** = 截断到该下标 + 把改后文本走 `_do_send` 重发（编辑框预填的是**用户原始输入**：`_user_message_text` 剥掉程序追加的 @ 引用提示与图片提示——否则重发会把提示当正文再追加一遍、越滚越长；原消息带图片时弹一行提醒「编辑重发只发文字、图片不保留」，图片块只存 base64 不存源路径、无法随文字重发，`_message_has_images` 按块结构判定）；**回退** = 截断并落盘；**分叉** = 把前缀复制成新会话（`fork_session`，继承模型/模式/权限/思考/分类，运行态从零、拿新 id），原会话不动。
- 后端核心 `truncate_history(sess, cut_index)`：在**同一 `snapshot_lock` 临界区**内截断历史 + 作废 compaction（`covered_upto` 是绝对下标）+ 按存活 ToolMessage 过滤 `evicted_tool_results` + `_clear_progress` 重置运行态（RLock 可重入）。`rewind_session` 再落盘：截断后 >1 条正常存盘覆盖旧正文；回退到空（只剩 SystemMessage）走 `delete_session(old_id, keep_file_history=True)`（存盘守卫 `len<=1` 会跳过空历史，故走删除），但**保留 `current_session_id` 与文件撤销材料**：磁盘改动并没被回退，顶栏撤销靠会话 id + file_history 定位，清掉 id 或删掉材料就让"回退到空"后的改动再也撤不回。
- **绝不撤销磁盘文件改动**：不碰 `file_history` 的记录/blob，顶栏「撤销」照常可用。没有"每轮进度快照"，所以回退/分叉把计划/台账/待验证义务/结果卡/任务身份重置为干净态，而非精确还原到某轮——诚实且无损坏。分叉的新会话 id 查不到旧撤销记录（不继承）。
- 都改/复制历史，先过 `_worker_alive(sess) or resume_pending` 闸（与 retry 同源：worker 还活着就拒绝，不排队）；回退另弹确认框说明"不撤销文件"。下标失效（消息已不在）→ 提示 + 重绘自愈。

## 会话重命名与跨会话搜索（src/memory.py + src/ui/sidebar.py）
- **重命名 `rename_session(session_id, title)`**：与 `move_sessions_to_no_project` 同样的"三处一起改"，同一 `_LOCK` 临界区内改 ① 内存里已打开会话的 `current_session_title`（经 `live_sessions()` 取一致快照；只改磁盘的话下次 `save_session` 会用旧内存标题覆盖回去——正常流程必现）② index.json 的 title ③ `<id>.json` 正文 title。**不刷新 `updated`**：改名是元数据编辑、不是新活动，不该把会话顶到分组最前打乱历史顺序。用户标题只折叠空白 + 截断 100 字符（`_sanitize_user_title`，不像自动标题那样剥标点/书名号）；空标题抛 `ValueError`。UI 走会话行右键菜单「重命名」→ `dialogs.get_text` 主题输入框（生成中也可改名，标题不动历史/运行态）。
- **自动标题 `maybe_generate_session_title`**：首轮结束后后台线程调一次模型（关思考）。提示里除了首句，还带第一轮助手最后一条有正文的回复开头（`_first_reply_text`，600 字）：首句只有网址 +「答一下」时，只看首句模型猜不出在做什么（实测回了「无法确定」，侧栏就叫这个）。模型整句回的是「无法确定 / 不确定 / 未知 / 抱歉…」这类（`_VAGUE_TITLE`，整句匹配，「不能启动排查」这种正常标题不误杀）就退回首句截断。测试 `scripts/test_session_title.py`
- **跨会话搜索 `search_sessions(query, *, kind=None, project="__all__")`**：先 `list_sessions` 拿索引（只在读 index 时持 `_LOCK`，读完即释放），再**锁外**逐个读正文（`_atomic_write_json` 保证读到完整旧/新文件）。只搜真实用户输入 + 助手可见正文（`content_text` 跳过思考块），跳过 SystemMessage / 内部消息（`lingxi_internal`）/ 工具结果；大小写不敏感。结果按索引顺序（更新时间倒序），每项含 `snippet`（首个命中处上下文预览）/ `match_in_title` / `match_count`。单个正文读不出（损坏/版本过新）只跳过其正文、保留标题命中，不中断整次搜索。
- **搜索 UI 不卡主线程**：侧栏「历史记录」下的搜索框防抖 250ms（回车立即搜），扫描放 daemon worker，结果经 `SignalBridge.session_search_done(str, object)` 回主线程渲染。**worker 必须继承启动时刻的数据根**（`paths.get_data_dir()` → 线程内 `set_data_dir`，与 send worker 同套路）：`set_data_dir` 是线程本地的，不继承则 Web 多用户模式读到默认根（别人的数据）、测试读不到隔离目录。搜索态下 `_refresh_session_list` 改渲染扁平结果行（标题 + 项目名 + 命中预览，点击 `_load_session` 跳转）；过期结果（查询词已变）丢弃；切工作区（`switch_workspace`）清空搜索（kind 变了旧结果失效）。

## MCP 客户端（src/mcp_client.py，可选功能）
- 让灵犀连外部 MCP server（filesystem / fetch / context7 / memory 等），把远程工具动态注入到 `ALL_TOOLS`，跟内置工具一样被 AI 调用。**没装 `mcp` 包 / 没配 `mcp_servers` 时整段静默跳过**（零回归）
- 配置在 `config.json` 的 `mcp_servers`（dict，key=server 名）：`transport` 支持 `stdio`（command+args）/ `sse`（url）/ `streamable_http`
- **同步/异步桥接**：mcp SDK 是 asyncio 异步、灵犀 agent 是同步。`mcp_client.py` 起**一个常驻后台线程跑 asyncio loop**；每个 server 一个常驻协程，`async with stdio_client/sse_client ... await _shutdown_event.wait()` 挂住保持连接（**绝不能 return session 出去，上下文一退连接就断**）。工具调用走 `run_coroutine_threadsafe(session.call_tool(...), loop).result()` 从 agent 线程投进 loop
- **致命坑（已避开）**：不要在 loop 自己的线程上对同一 loop 用 `run_coroutine_threadsafe().result()` —— 自死锁。`_build_mcp_tools` 是纯同步、读 `_server_loop` 提前缓存好的 `_server_tools`
- **包装工具**：`_wrap_mcp_tool` 逐个包装，一个工具出错只跳过它并记日志（异常冒到守护线程会让整个 loop 退出、已连上的 server 一起断）。`requirements` 是 `mcp>=1.9`：1.x 的字段是驼峰（`inputSchema` / `isError`），2.x 改成下划线（`input_schema` / `is_error`），统一走 `_field` 两种都认；参数 `type` 可能是列表（如 `["integer", "null"]`）。工具结果 `is_error` 时返回「MCP 工具报错：…」。stdio 启动前先查命令存不存在，找不到直接说缺哪个命令
- 工具名加 `mcp_{server}_{tool}` 前缀（防撞内置工具）；`_execute_tool` 里 `name.startswith("mcp_")` 的工具走**执行前确认**（MCP 工具能干任意事）；Plan 模式当写工具拦截
- 启动时 `agent.py` 后台线程调 `init_mcp()`，工具就绪后清 `_BOUND_LLM_CACHE` 让下次 stream 重新 `bind_tools`；关窗 `main.py` 调 `shutdown()`；`mcp_servers` / `mcp_enabled` 改了由设置热更新在后台 `restart()` 重连（见 core.md「设置热更新」）
- 打包：`lingxi.spec` 用 `collect_submodules('mcp')` + `collect_data_files('jsonschema_specifications')`（懒导入 + 数据文件，静态分析抓不到）

## RAG 知识库检索（src/rag/ + tools_rag.py）
- 对一个本地资料目录（`config.json` 的 `rag.kb_dir`）做语义检索，`search_knowledge` 工具返回带 `[n]` 编号和出处的片段，模型据实回答并标来源。`kb_dir` 为空 = 未启用
- **摄取**：`.md` / `.markdown` 走标题分层切块（标题路径拼进 embedding 文本提升召回）；`.pdf` 用 pypdf **按页切**、`heading` 填「第 N 页」（引用能定位页码），且**不做 Markdown 解析**——PDF 正文里的 `#` 和 ``` 只是普通字符，当成语法会凭空造出错误标题、还会因围栏状态翻转让后续切块全错
- **分域（category）**：`kb_dir` 下的**顶层子目录名**即分域名，根目录下的文件归 `default`。检索时 `scope="all"` 且索引里有多个域 → **每域各查一遍、按名次轮转合并**（`retriever._balanced_search`），某域取完名额自动让给其它域。解决「同一个库里放了两批同题材资料」时的相互挤占——比如项目实现文档与通用学习资料都在讲 MCP/RAG/Agent 主循环，标题几乎一样、向量空间里天然难分，不分域的话 top-k 会被其中一批占满，模型据此把别人的做法当成你的（**张冠李戴**，比返回噪声更难发现）
- **`min_score` 是必须设的**：`retriever` 里 `if min_score > 0` 才过滤，设成 0 等于**整个阈值机制关闭**——无论问什么都硬凑满 `top_k` 条，`tools_rag` 里「知识库中没有相关内容」那条兜底路径变成死代码。分域配额会保证另一个域也拿到名额，正是靠 `min_score` 把其中不相关的那些剔掉，两者配套
- **向量库 = Chroma**（`store.py`），落盘 `chat_memory/rag_index/chroma/`。三项关键保证：
  - **chunk hash 当 document ID** → 「哪些块已 embed 过」退化成「哪些 ID 已存在」，不需要单独的向量缓存文件；附赠内容去重（同一份资料的多个副本不会各占一个 top-k 名额）
  - **staging + 改名式事务提交**：数据先全写进 `kb_x_v1__staging`，提交时 main→`__old`、staging→main、删 old。Chroma 没有事务，靠 `load()` 的 `_recover` 从残留状态推断该回滚（main 不在、old 在）还是该前滚（main 在、有残留），绝不出现「新向量 + 旧元数据」或索引凭空消失
  - **索引锚**：manifest 整体 `json.dumps` 存进 collection metadata 的 `lingxi_manifest` 键（存字符串绕开 Chroma 的 metadata 取值类型限制 + 保留键前缀）。换目录/换模型/换端点/改切块参数没重建 → `anchor_mismatch` **fail-closed** 抛 `IndexMismatchError`，绝不拿旧索引答题。`index_status`（UI 状态行）与 `retrieve`（实际检索）共用同一判据，杜绝两处漂移
- **会话锚定知识库** `Session.rag_kb_dir`：首次成功检索时绑定当时的 `kb_dir`，之后配置切库不影响该会话——历史会话不会静默检索到另一个库。空锚点只在**检索确实跑在有效索引上**之后才绑定（未建索引的失败检索不该钉死一个空会话）
- 旧版 numpy 散文件索引（`rag_index/<name>/*.npy`）不兼容，检测到只提示重建
- **侧栏读索引状态在后台线程**（`rag_sidebar._refresh_kb_status` → `_read_kb_status_async` → `bridge.kb_status_read`）：第一次 `index_status` 要加载向量库、打开索引，实测 1.77s（第二次 0.03s），早先放主线程，第一次从编码切到知识库整个界面卡住。结果带请求序号，只认最新一次（期间换目录 / 开始重建的旧结果丢弃）；同一目录同一套配置读过的直接先显示（不闪「读取中」），重建后缓存作废；启动 2.5s 后空闲预热一次（`_prewarm_kb_status`）。实测首次切换主线程 0.02s

## 长期记忆（src/memory_store.py，跨会话）
- 让角色"天生记得"用户：`remember(fact)` / `forget(query)` 两个工具存取，`get_system_prompt()` 末尾自动注入记忆（不靠 AI 主动查，开口就记得）。**注入有预算**：`render_memories_for_prompt(max_chars=MEMORY_MAX_CHARS)` 默认 4000 字符，超出保留最近的——不是"无限全量注入"
- 存 `chat_memory/long_term_memory.json`（`{memories: [{id, text, created, scope}]}`，scope 默认 global）。独立 `RLock`，跟 `memory.py`（会话历史）分开

## 主题弹窗（src/ui/dialogs.py）
- **`src/ui/` 里不用原生 QMessageBox / QInputDialog**，一律走 `dialogs`（守它的是 `scripts/test_themed_dialogs.py::test_no_native_message_or_input_boxes_in_ui`，按 tokenize 只看代码里的名字）。QFileDialog 文件选择框和托盘气泡保留原生。设计稿是画布「灵犀弹窗设计」：无边框、背后一层变暗的遮罩、中间一张宽 440 圆角 14 的卡片；颜色全取 `theme` 的 `dlg_*` token（打开那一刻按当前主题取），明暗两套 key 必须一一对应
- **实现：窗内覆盖层**（`_OverlayMixin`，ThemedDialog / CardDialog 共用）：有可见的父窗口时，弹窗是**父窗口里的子控件**（`Qt.Widget`），盖满客户区画遮罩，卡片在中间偏上（上下留白 4:6）。最早做成盖在父窗口上的无边框顶层窗，结果是应用级模态——Windows 下主窗口标题栏的最小化 / 最大化 / 关闭都点不动（用户实测），窗口放大后遮罩也不跟着变。现在：标题栏按钮照常可点；父窗口装事件过滤器，缩放时遮罩和卡片跟着重排；遮罩吞掉鼠标；Tab 焦点只在弹窗里转（`focusNextPrevChild`）；`ShortcutOverride` 在弹窗接住，主窗口的快捷键不会越过弹窗触发；没处理的按键不往主窗口冒；关掉后焦点还给打开前的控件。仍是 `exec()`（QDialog 自己的局部事件循环），调用处保持同步写法，只能在主线程调。父窗口不可见（最小化 / 进托盘）或没给 parent 时退回无边框顶层窗：只开卡片大小、屏幕居中、不画遮罩
- **API 对齐 QMessageBox**：`question / information / warning / critical / success` 返回 `StandardButton`（数值与 QMessageBox 一致），`labels={dialogs.Yes: "删除"}` 改按钮字；`choose` 多出口返回动作 key（Esc / 关闭返回 None）；`get_text` 同 `QInputDialog.getText` 返回 `(文本, 是否确定)`；`confirm_danger` 返回 bool。图标底色表示类型：info 靛蓝 / success 绿 / warning 琥珀 / error 红，`glyph` 另选图形（rewind / trash / folder …）。路径和报错放 `detail`（灰色等宽框，带「复制」，长路径无空格也能折行：用 QTextEdit 不用 QLabel）
- **键盘**：Esc = 取消（关闭按钮、Alt+F4 同）；Enter = 默认按钮——普通对话框默认主按钮，调用方给了 `default` 按它（回退对话、移除项目沿用原来的默认「取消」），焦点在别的按钮上时按那个；**危险对话框（`danger=True`）默认聚焦取消，Enter 永远等于取消**，危险按钮只能点或 Tab 过去按空格（原来「跳过权限确认」的 QMessageBox 按 Enter 就直接切了）。按钮自绘（`DialogButton`）：主窗口的全局 QSS 会继承下来，焦点环又要画在按钮外面，QSS 盒模型做不到；autoDefault 关掉，Enter 统一由对话框处理
- **危险样式的调用点**：跳过权限确认（琥珀图标 + 红按钮「仍要切换」）、删除自定义模型。危险按钮实心 #c43d27（深色主题 #f09a8d 配深色字），对比度都过 4.5:1（测试里算）
- **表单对话框用 `CardDialog`**（设计稿「设置对话框 · 应用内外框」）：同样是无边框透明窗 + 遮罩，卡片圆角 16，顶部 56 高的标题栏（标题 + 关闭），中间 `self.body` 由子类排，底部 64 高的操作栏（左边一行说明 `set_hint`，右边 `add_button(文字, 角色, 槽, default=)`）。卡片按请求的宽高放中间，窗口小了就缩到窗口里留 32 边；Esc / 关闭 = reject，Enter 走 QDialog 的默认按钮。**子类的内容样式设到 `self.body` 上**，设到对话框本身会把遮罩和卡片的样式盖掉。用它的：设置（800×620，原来的 QTabWidget 只藏起标签栏，左侧 168 宽的导航按钮切页；roles / logs / config / 关于收在导航底部；操作栏说明写「保存后立即生效」，见 core.md「设置热更新」）、自定义模型编辑、编辑固定限制（字数 / 拒绝保存的说明在编辑框下面，放操作栏会被挤成几行裁掉）、只读长文本 `TextViewerDialog`（验证输出，带「复制全部」）。退出确认 `QuitConfirmDialog` 是危险样式的 ThemedDialog（托盘里退出时主窗口隐藏，只开卡片、屏幕居中）；编辑消息 / 编辑排队消息改用 `get_text(multiline=True, banner=…, rows=6)`（设计稿是 4 行，消息编辑给到 6 行），Ctrl+Enter 确定

## 自绘标题栏（src/ui/titlebar.py）
- **目的**：去掉 Windows 那条白色系统标题栏，最小化 / 最大化 / 关闭放进我们自己的顶栏（用户参照的是 Claude 桌面版顶栏），同时**保留系统窗框的所有行为**：拖边改大小、拖到屏幕边贴边、Win11 鼠标停在最大化键上弹分屏布局、最小化 / 最大化动画、DWM 阴影和圆角
- **做法**（业内常见的「无边框 + 原生样式加回来」）：`ChatUI.__init__` 里 `FramelessController` 设 `FramelessWindowHint`（Qt 不再留标题栏），第一次 showEvent 用 Win32 把 `WS_THICKFRAME | WS_CAPTION | WS_SYSMENU | 最小化 / 最大化` 加回窗口样式，`DwmExtendFrameIntoClientArea` 留 1px 让阴影出来。`ChatUI.nativeEvent` 交给控制器：`WM_NCCALCSIZE` 把非客户区收成 0；**最大化时把客户区夹到显示器可用区域里**（`MonitorFromWindow` + `GetMonitorInfo` 的 rcWork），任务栏自动隐藏时底边再留 2px。两个坑（都是实测）：① 不能固定往里收一圈窗框厚度——Qt 自己最大化无边框窗口时已经把窗口摆成正好等于可用区域，再收一圈就成了「伪全屏」：四周露出一圈窗框，底边和右上角被裁掉；系统路径（拖到屏幕顶、系统菜单）最大化时窗口又是超出屏幕 11px 的矩形，夹到可用区域两种都对；② 判断最大化要问系统 `IsZoomed`，这条消息来的时候 Qt 的 `isMaximized()` 还没更新。`WM_NCHITTEST` 走 `hit_test`：四边 6px 改大小（最大化时没有）；顶部 56px 里不是按钮 / 输入框 / 有标签的地方报 `HTCAPTION`（拖动、双击最大化、右键系统菜单都是系统的）；我们的最大化键报 `HTMAXBUTTON`（Win11 分屏布局靠它），这时 Qt 收不到它的鼠标事件，悬停在命中测试里记、点击在 `WM_NCLBUTTONDOWN / UP` 里处理
- **最大化 / 还原走系统**（`WindowButtons.toggle_maximized` 调 `ShowWindow(SW_MAXIMIZE / SW_RESTORE)`），是不是最大化也以系统为准（`is_maximized` 问 `IsZoomed`）。Qt 的那一套对无边框窗口不可靠（用户实测「按钮不好使、拖动不变小」）：`showMaximized()` 只是把窗口摆成屏幕大小，系统不认为它最大化了，拖标题栏系统只当普通移动，窗口整块挪走不缩小；系统那边最大化（双击标题栏、拖到屏幕顶、Win+↑）之后 `showNormal()` 什么都不做。走 `ShowWindow` 时 Qt 的窗口状态会跟着 WM_SIZE 自己更新；`WM_SIZE` 里也同步一次按钮图标（Qt 状态没变、不发 WindowStateChange 的情况）。`scripts/titlebar_native_check.py`（`test_titlebar` 起子进程，Windows 平台插件下开透明真窗口）测这一半
- **布局（参照 Claude 桌面版）**：顶栏一整行横跨对话区和右侧面板（`_build_ui`：侧栏 | [顶栏 ; 对话区 | 文件面板 | 任务面板]），窗口按钮 `WindowButtons`（46×56，和顶栏一样高，图标和顶栏按钮在一条线上，关闭键悬停红底白字）是顶栏这一行的最后一项；右侧面板自己的标签行和关闭 × 在顶栏下面。早先窗口按钮浮在窗口右上角、右侧面板的标签行也在最顶上，两个 × 挨在一起分不清（用户实测），所以改成这样
- **一开始就走 GPU 合成**（main.py 设 `QT_WIDGETS_RHI=1`，Windows 上、没选系统标题栏时）：第一次嵌入浏览器页面（GPU 渲染的控件）时，Qt 会把主窗口的原生句柄销毁重建——窗口闪一下，加回去的窗框样式也丢了（实测句柄变了、WS_THICKFRAME 没了）。一开始就用 GPU 合成，嵌入时句柄不变；`_WinIdWatcher` 在句柄万一变了时重新加窗框样式兜底
- **只在 Windows 平台插件下启用**（offscreen 测试不走）；`config.json` 的 `native_title_bar: true`（设置 → 高级 → 窗口）退回系统标题栏，重启生效——自绘标题栏在某台机器上显示不对时的退路。测试 `scripts/test_titlebar.py` 测命中测试、让位和按钮，最大化 / 还原起子进程在真窗口上测；其余 Win32 部分（贴边、分屏、阴影）只能实机看

## 右键菜单（src/ui/context_menus.py + browser_panel 的网页菜单）
- **为什么**：Qt 自带的输入框 / 文本框右键菜单是英文（Undo / Copy / Select All，没加载翻译），Chromium 的网页菜单也是英文（Back / Reload / Inspect）。设计稿是「右键菜单 · 输入框与聊天记录」「右键菜单 · 浏览器网页」两板
- **文本类控件**：`ChatUI.__init__` 调 `context_menus.install(app, host=self)`，在 QApplication 上装一次事件过滤器。`QEvent.ContextMenu` 落在 QLineEdit / QTextEdit / QPlainTextEdit（事件先到视口，换成编辑框本身）/ 可选中的 QLabel 上、且它的 `contextMenuPolicy` 是默认值时，换成我们的菜单；自己有菜单的控件（CustomContextMenu，比如侧栏会话行）不碰，单个控件要保留原生菜单就设属性 `lx_native_menu`。能编辑的：撤销 / 重做 · 剪切 / 复制 / 粘贴 / 粘贴为纯文本（`acceptRichText` 的 QTextEdit 才有）· 全选，按状态置灰，密码框不给复制剪切；只读的：复制 ·（聊天正文）复制为 Markdown · 引用到输入框 · 链接项 · 全选
- **聊天记录**：每段正文是 `message_view.BodyText`（QLabel）。`finalize_markdown(html, md)` 把源文存进属性 `lx_markdown` 给「复制为 Markdown」；QLabel 不能按位置查链接，`linkHovered` 时把链接记进 `lx_hover_link`，右键时据此给「在浏览器面板打开」（本机地址）/「在系统浏览器中打开」（公网）/「打开」（文件链接）+「复制链接地址」，走 `ChatUI.context_menu_open_link` = 点链接同一条路。「引用到输入框」= `ChatUI.context_menu_quote`：每行前加 `> ` 追加到输入框末尾
- **网页**：`BrowserView._embed` 把 view 设成 CustomContextMenu，按 `lastContextMenuRequest()` 拼：可编辑区域给编辑项（按 editFlags 置灰）；链接给 打开链接 / 复制链接地址 / 在系统浏览器中打开链接（+ 有选中时复制 / 把选中文字发到输入框）；选中文字给 复制 / 发到输入框；空白处给 后退 / 前进 / 重新加载 / 复制页面地址 / 在系统浏览器中打开；最后都有「检查元素」（开停靠的开发者工具 + InspectElement）
- **选中文字浮出「引用 · 复制」也挂在这个过滤器上**（`_maybe_show_bar` / `_dismiss_bars`）：松开左键时选中了消息流里的只读文本就叫出 MessageView 的 `selection_bar`（零秒后再看选区，等控件自己处理完这次松开）；按下鼠标（点在浮条上除外）、Esc、弹右键菜单就收。只多判三种事件类型，没有另装过滤器。详见 core.md 消息流「引用」
- **性能：批量建控件时摘掉过滤器**（`context_menus.suspended()`，可嵌套）：应用级过滤器是 Python 写的，界面上每个事件都要进一趟 Python。人手操作时事件稀，感觉不到；重画长会话（371 条消息、92 张工具卡）一口气约 9 万个事件，「知识库切回编码」从 0.8s 变成 1.6s、打开长会话 1.1s → 2.0s（用户发现「之前不卡」，按提交逐个检出二分，定位到本节引入的这一批）。`_redraw_chat` 包在 `suspended()` 里，修后回到 0.82s / 1.0s。重画期间主线程忙，不可能弹右键菜单；期间的右键事件排队，装回之后才分发。以后加应用级 Python 过滤器要先想这个账
- **外观**：`make_menu` 给的 QMenu 圆角 10、内边距 6、项高约 32、选中靛蓝浅底，颜色取主题的 `menu_*`（打开那一刻取）；圆角要透明底，系统阴影是方的，所以去掉阴影用描边。快捷键只显示（文字里制表符后面那段右对齐），不注册成真的快捷键

## 侧栏浏览器（src/browser/ + tools_browser.py + ui/browser_panel.py）
- **面板长相**（`ui/browser_panel.py`，第 4 批照设计稿重做）：标签显示页面图标 + 标题，模型操作中带小圆点，出错显示「无法访问」（`file_panel._BrowserTabLabel`，`tab_state_changed` 驱动）。工具栏：后退 / 前进 / 刷新（加载中变停止）、地址胶囊（左边的来源标签：本机 · 已信任 / 本机 / 已信任 / 外部网站，按正在跑的驱动会话、否则前台会话的 `browser_origin_allowlist` 判定；不在编辑时从头显示网址）、F12、更多（系统浏览器打开 / 复制网址 / 关闭浏览器）；下面 2px 加载条。内容区三态：**空白**——列出后台任务里正在跑、`dev_server_url` 认得出的本机服务（点「打开」= 人主动打开灵犀自己起的服务，来源加进任务所属会话的白名单，和后台面板同一规则）+ 本次运行「最近打开」（进程内、不落盘）；**浏览中**——模型操作时页面描 2px 靛蓝边、底部浮状态卡「灵犀正在点击」+ 第几步 +「停止」（桥 `activity` 驱动，两次动作之间 900ms 内不收，免得一闪一闪）；「停止」停的是**驱动浏览器的那个会话**（`bridge.driver_session()`，`call()` 时记下的 worker 会话）：是前台会话走停止按钮那一套，后台会话只置它的 `stop_flag`；**连不上**——`loadingChanged` 报 LoadFailed（排除 ERR_ABORTED 和 HttpStatusCodeDomain，见下条）时换成我们自己的错误页（重新加载 / 本机地址才给「去后台看看」/ 错误码），不用 Chromium 的英文页，模型读到的仍是页面本身。开发者工具停靠在页面下方（可拖分隔条、可弹成单独窗口；同一页面只能挂一份，弹出时停靠的那份收起），关标签时先拆开发者工具再释放页面。停靠栏顶部改成标签行在最上（右端「浏览器」入口和收起 ×），文件路径 / 说明只在文件标签下出现。**「收起 ×」只隐藏面板**（`collapse`）：文件标签、网页标签、页面 / cookie / 登录态全保留；用户收起记在 `_user_collapsed`，响应式布局（窗口变宽）不自动弹回，地球按钮 / 点文件链接 / 后台按钮这些显式入口才恢复（`_show_self` 清标记）。模型收起期间开新标签、或在原标签里 `browser_open`，都会弹回面板（`page._notifier.model_opening` → `ChatUI._on_model_browser_opening`：面板没显示才弹，开着不抢标签）——不弹回的话模型在看不见的页面上操作（真实点击退回脚本点击、隐藏页面定时器被节流），用户也看不见它在干什么（review 实测）。真关浏览器只有三个口子：网页标签 ×（最后一页等于关浏览器）、「更多 → 关闭浏览器」、模型 `browser_close`。地球按钮（`open_last_browser`）浏览器还活着（含收起只是藏着）时只切过去、不导航；关过就是空白新标签——不再复用上次地址：用户点了网页标签 × 再点地球，上次那页又自己开回来，像是没关掉（用户实测）。上次那页在空白页的「最近打开」里。标签条上最后一个标签后面有 + （`new_tab_btn` → `new_browser_tab`，用户要的）：有网页标签才出现，开空白网页标签、切过去、光标落在地址栏；开满 `MAX_TABS` 在当前页上提示，不再开。标签条不占满整行（stretch 0 + 后面一个弹性空白），+ 才能紧跟在标签后面收起期间网页不可见：模型真实点击退回脚本点击、截图报错（见下面两条，结果里都明说）
- **模型和人共用一个页面**：浏览器在文件面板里开一个「浏览器」标签（`BrowserView`），嵌的就是 `page.get_browser().view`，模型的导航 / 点击在面板里实时可见。**懒加载是硬约束**：`browser/`、`tools_browser.py`、`browser_panel.py` 顶层都不 import QtWebEngine*，profile / page / view 等到第一次 `browser_open` 或手动点开标签才在主线程构造，不用浏览器就不存在
- **profile 常驻、off-the-record、NoCache**：`page._get_profile()` 不传 storageName（只在内存、不落盘）、不设 parent（模块持有；offscreen 下进程退出前销毁用过的 profile 会触发上游 Qt 段错误），关浏览器只销毁 view/page。关闭时清 cookie、visited links，HTTP 缓存只**标脏**、由下一次导航先清；localStorage 没有清除 API，留到进程退出。安全默认值：下载、alert/confirm/prompt、摄像头/麦克风/定位/通知一律拒（新窗口见下面的多标签），`acceptNavigationRequest` 只放 http(s) 和 about:blank
- **每次导航前清渲染进程的内存缓存**：NoCache 管不到 Blink 的内存缓存，它按 Last-Modified 认为旧脚本"还新鲜"——改完 app.js 重开同一地址、加 `?v=2`、Reload 都还跑旧代码（评测 012）。桥的 open 对非空白页先 `clearHttpCache()`，等 `clearHttpCacheCompleted` 再 `page.load`。**导航在途时不清**（`_page_loading`）；新页面 / about:blank 直接 load（关过浏览器则因标脏先清一次）
- **缓存闸门：清缓存和导航绝不重叠**（`page.load_url` / `clear_cache_then` / `when_cache_idle`）：`clearHttpCache` 发出前后紧挨着开始的导航，`loadStarted` 之后再也等不到 `loadFinished`，卡满加载超时（离线探针：load 前后紧挨着清 8/8 卡死；`clearAllVisitedLinks` 不受影响）。所以**模型的 open 和面板的地址栏 / 刷新都走闸门**：有清理在途就排队等清完；清理一次只跑一个，第二次要清就排在同一次后面（叠两次时，前一次的完成信号会把后一次等着的导航提前放行）；5 秒没回完成信号才按完成处理并记日志。曾经「关浏览器马上重开偶尔卡 20 秒」就是这三个口子：关闭后轮询到桥空闲才清——面板自己的导航不经过桥，模型的 open 也可能刚好落在「判定空闲」之后；以及上面两条。新增导航入口必须走 `load_url`，回归用例 `test_navigation_waits_for_an_in_flight_cache_clear` 在同一轮事件里紧挨着发清理和导航（经 worker 线程转一手就有几毫秒间隔，撞不上，测不出闸门）
- **tree.js 注入隔离世界**：`QWebEngineScript` 在 DocumentCreation、ApplicationWorld、含子 frame 注入，页面脚本看不到也改不了 `window.__lx`，闸门用的 info/state 才可信；`runJavaScript` 必须用同一个 worldId。隔离世界拦不到页面的 `console.*`，页面控制台走 `ConsolePage.javaScriptConsoleMessage` 这条 Python 通道
- **worker ↔ 主线程的桥**（`bridge.py`）：工具跑在 worker 线程，`call()` 经 Signal 投到主线程（`BrowserBridge` 建好后 `moveToThread(app.thread())`），自己在 `threading.Event` 上每 0.3s 分片等待、看 `stop_flag`，点停止立刻发 cancel 返回。**不能在主线程调 `call()`**：请求排在主线程事件队列里，主线程却在 `ev.wait` 上等它，死锁。`open` 也不嵌套 QEventLoop——嵌套期间主线程会处理关窗等事件，窗口关掉后访问已删除控件会崩；改成 loadFinished 回调写结果 + 带 receiver 的 QTimer 管超时
- **HTTP 4xx/5xx 带内容不算「连不上」**（复审 #13）：`loadFinished(false)` 比 `loadingChanged(LoadFailedStatus)` **先到**（实测），桥收到失败先等失败域（域信息到了立刻判，150ms 没到按真失败报，带 receiver 的 QTimer）；`HttpStatusCodeDomain` → `ok=True` + `httpStatus`，`browser_open` 注明「服务器返回 HTTP N」并附快照——Flask 调试页的 traceback 模型读得到（`browser_read_text` 读全文）。加载记录带上状态码（`browser_last_load.http_status`），之后读控制台时 4xx/5xx 记成**失败**的浏览器检查（「页面返回 HTTP 500」，`browser_check.errors` 多算一条）——review 实测：500 页面之后控制台干净，曾被记成「浏览器控制台：通过」，服务崩了结果卡却说检查通过。面板对这个域也照常显示页面、不盖错误页。错误页的错误码栏清洗 Qt 未替换的翻译模板（`<strong>$1</strong>` → 去标签、填错误码）
- **ref 跨文档单调递增、执行时核对 docId**：tree.js 每个文档生成一个 `docId`，ref（`e12`）在同一文档里稳定复用；桥用 `_ref_seed` 记已发过的最大编号、下一个文档接着往上数，换页后旧编号不会撞上新元素。`tools_browser._issued` 登记每个 ref 签发时的 docId，`click/type` 执行前先比对当前 docId，换了文档或配错 frame 一律报"ref 已失效"。签发的来源有三处：snapshot、find，以及**动作后算变化用的那份快照**（`_delta_text` 里 `_remember_refs(after, frame)`）——变化行里露出来的新按钮带着 ref，模型照着点是自然的；以前不登记，B 站小游戏里弹窗按钮 6 次都被拒（用户实测）
- **动作后「已导航」按文档编号判**（`_changed_document`）：前后快照的 docId 不同才算换了文档、旧 ref 全失效；单页应用改路由只换地址，报「地址变成了 …（ref 照常可用）」；没有 docId 时退回比地址。比的地址是**动作所在文档**的：iframe 里动作传 frame 的地址（`_after_action(before, frame, frame_url, …)`）。以前一律传顶层页面的地址，frame 里取的快照带回 frame 自己的地址，两者永远不等——iframe 里每点一下都报「页面已导航，旧 ref 全部失效」，文字树没变时还因此跳过了样式核对
- **面板刷新 / 地址栏拿到新代码**（复审 #14）：刷新键走 `WebAction.ReloadAndBypassCache`（普通 Reload 照样用缓存里的旧 app.js）；地址栏 / 面板 `navigate` 打开**本机地址**时 `load_url(clear_first=True)` 先清 HTTP 缓存（和模型的 browser_open 一样），公网站点不清（资源大多带指纹，清了只是白白重下）。页面正在加载时不清（和在途导航一起清会卡住），这是 `load_url` 原有的规矩
- **离开确认放行一次**（复审 #15）：页面的 beforeunload 走 `javaScriptConfirm` 通道，以前一律拒绝——用户在页面上点过、页面挂了「有未保存的修改」，模型再 browser_open 就卡满超时，面板后退 / 跳转没反应、刷新键停在「停止」。我们自己发起的跳转（`load_url` 里 `page.load` 之前、面板的前进 / 后退 / 刷新）先 `page.allow_leave(p)`，`LEAVE_CONFIRM_WINDOW_S`（5 秒）内弹出的那一次 confirm 放行；**新页面一开始加载（loadStarted）就收回**——离开确认一定在导航真正开始之前（被拒的话导航根本不开始），不收回的话旧页面没挂 beforeunload 时这次放行会留给新页面自己的 confirm()（实测：刚打开的页面上点「删除」被当成同意）。**放行只认离开确认本身**（`page.is_leave_prompt`：beforeunload 走 confirm 通道时 Qt 给的是一句固定英文，页面在 returnValue 里写的字被忽略，实测 Qt 6 一律如此，应用没装 Qt 翻译）——单页应用里后退 / 前进、只改 #hash 是同文档导航，没有 loadStarted 收回窗口，以前这 5 秒里页面自己的 confirm（「确定删除吗」）不问用户直接当同意（2026-11-24 排查 B1）。页面自己弹的 confirm 照旧拒绝 / 问用户
- **打开的边界**（2026-11-24 排查 B2 B3）：① 页面有导航在途（用户在面板里点的链接、热更新整页刷新）时模型 `browser_open`：新导航顶替在途的那个，Qt **不再发 loadStarted**，只来一个 loadFinished（实测）；以前它被当成上一个导航的迟到信号丢掉，卡满超时报失败、页面其实已打开。`load_url(on_go=…)` 告诉调用方发出那一刻页面是不是在加载，`bridge._on_open_sent` 据此直接记成「已开始」。② 只差 #hash 的地址（hash 路由的单页应用）或带 # 原样重开：Chromium 当同文档导航，**不重新加载、也不发开始 / 完成信号**（完全相同的带 # 地址连 urlChanged 都没有）——以前 open 卡满超时、改完代码重开还跑旧的，面板刷新键停在「停止」。现在 `load_url` 认出这种情况（`_same_document`）就在页面里 `location.href = 目标; location.reload()`，整页重新加载，信号照常来；模型和面板地址栏都走这条
- **富文本框的名字**（复审 #11）：组件库里的编辑器是包了好几层的 contenteditable，表单标签的 for 指向不存在的 id，快照里只剩无名 textbox，模型分不清标题和正文（实测 antd 表单里两个 Quill）。`tree.js` 的 `orphanLabelFor`：往上最多 8 层，找「不在它里面、for 没对上别的控件」的 `<label>`；**只在这一层恰好一个这样的标签、除了它再没有别的可见输入控件**时采用，分不清就不取名（不能把标题的名字安到正文上）；再不行用 aria-placeholder / data-placeholder / placeholder
- **边角**（复审 #12）：iframe 里的 `blob:` / `data:` 子框架放行（`acceptNavigationRequest` 只对子框架；顶层仍只放 http(s)）；没有表单时的「输入 + 回车」按真实顺序发 keydown → keypress → keyup，`keyCode` / `which` 放在构造参数里（我们在隔离世界，事后在实例上 defineProperty 页面脚本看不到）；变化行超过上限时先列新增的行、消失的只报行数（单页应用换路由整页都变，以前「-」行占满上限，新页面全被截掉）
- **几个会话共用一个浏览器**（复审 #22）：浏览器工具套 `_exclusive`，同一时刻只跑一个动作（一个动作是动作前快照 → 点 / 输入 → 动作后快照 + 样式核对一整串，交错着跑，变化 diff 和 tree.js 全局那份样式基线就互相覆盖）；排队时每 0.2 秒看一次停止标志。上一次用浏览器的不是这个会话（记会话 id）就在结果开头提醒「刚被另一个会话用过，先 browser_snapshot」（browser_open 不提醒：它本来就要换页面）。**没有做每个会话各开一个浏览器**：cookie / 登录态共用正是想要的（用户在面板里登录一次，各会话都能用），真要隔离得每个会话一套标签和当前页，代价大，先不做
- **网页弹框 / 下载 / 证书 / 登录**（复审 #16 #17，设计稿「侧栏浏览器 · 网页弹框、下载、证书、登录」）：**谁触发的决定问不问**——浏览器工具正在跑（`tools_browser._tool_lock` 被占着，`page.model_acting()`）算模型触发：alert / confirm / prompt 按取消、下载拦下、证书不放行，记进 `page.model_events`，`_exclusive` 在动作结束后取走、`_events_text` 写进工具结果（网页写的字——弹框内容、文件名——进不可信围栏）；以前只在控制台留一行，模型常以为「点了没反应」再点一次。**模型的工具在等别人时不算**（`page.model_waiting()`，2026-11-24 排查 B4）：锁在整个工具调用期间都占着，包括等用户点确认卡、`browser_screenshot` 等识别模型那十几秒；以前这期间用户自己在网页上点出来的确认框被静默取消、还写进模型的工具结果，模型以为是自己点出来的。`_gate` 等卡片、截图等识别模型时包一层 `model_waiting`，期间 `model_acting()` 为假。其余时候算用户在面板里点的：经界面层注册的同步回调（`page.set_ui_hooks`，`ui/browser_dialogs.make_hooks`，文件面板构造时注册）弹主题卡片问用户——Qt 要求 confirm 当场返回、下载在 downloadRequested 里当场 accept，所以是 exec() 模态。① 网页弹框 `PageDialog`：标题「网页提示 / 网页要你确认 / 网页要你输入」，网页的话放灰底框、上面标「本机 / 网站 + host 上的网页说」（网页的字不冒充灵犀），可勾「这个网页别再弹框了」（按来源记在这个标签的 page 上，之后直接取消）。③ 下载 `DownloadDialog`：取消 / 另存为…（原生 QFileDialog）/ 保存到「下载」（同名加 (1)，不覆盖），存好后面板底部 `_DownloadBar`「已下载 … 打开 · 在文件夹中显示」8 秒后收起。④ 证书：`certificateError` 里用户点过「仍然访问（只这次）」的本机 host:port 放行，其余一律拒绝；面板 loadingChanged 的 CertificateErrorDomain 画证书页（盾牌 + 琥珀色），本机且可跳过才给「仍然访问」，公网只给「返回」；放行表 `_cert_allowed` 关浏览器就清。⑤ Basic 认证 `authenticationRequired`：弹 `AuthDialog` 请用户填（模型触发的也弹——用户拍板），账号密码只交给网站，给模型的只有「登录了 / 取消了」；不填即取消（网站回 401）。没注册回调（测试、无界面）一律按取消
- **有后果的操作走权限闸门**：`security.decide_action` 按权限模式 × 动作分级 × 来源（本机 / 已授权来源 / 其它）给出 allow / ask / ask_always / block，要问就调 `ui.confirm_command(kind=KIND_BROWSER)`，没界面 fail-closed。`click/type` 先取元素 info，`is_consequential` 判定提交按钮 / POST 表单 / 回车提交，有后果每次都问、不给记住。提交按钮自己的 `formmethod` 盖过表单的 method（GET 表单里的 `formmethod="post"` 按钮以前被判成无后果）；React / Vue 的「onSubmit + fetch POST」表单不写 method、结构上像 GET，只能靠按钮名兜底，关键词含「确定 / 确认 / 保存 / save」，`ok` 按整词（不误中 book / token）。**表单内回车**（`submit=True`）= 浏览器替用户点默认提交按钮：按那个按钮的名字判（`tree.js` 的 `info` 给 `submitName`）；没写 method 的表单（`formMethodSet` 为假）同「表单外回车即发送」——信任的本机来源不问，其余都问；明写 `method="get"` 的仍按普通 GET 表单（2026-11-24 排查 B5：以前同一个评论框点「发送」每次都问，回车就直接发出去了）。**子 Agent 遇到有后果的直接拒绝**（浏览器不在 worktree 隔离里，点下去改的是真实数据），普通操作照旧不逐条问。浏览器**不套 fetch_url 的内网拦截**（localhost 正是主用途），内网风险靠只读导航 + 动作确认控
- **文字树里的状态**（tree.js `lineFor`）：勾选类控件原生 `<input>` 看 `checked` / `indeterminate`，自定义控件（`div[role=checkbox]` 等）看 `aria-checked`——早先只读 `el.checked`，自定义复选框永远显示 `[unchecked]`（实测）；另有 `[pressed]`（aria-pressed）、`[selected]`（原生 option 或 aria-selected）、`[disabled]`（含 aria-disabled），以及计算样式带删除线的 `[strikethrough]`（待办「已完成」最常见的画法）。规范里定死的其余状态也一次读齐：`[current]`（aria-current）、`[sort=…]`（aria-sort）、`[invalid]` / `[required]` / `[readonly]`、`[busy]`（aria-busy）、`<details>` 的 summary 补 `[expanded=…]`、Radix / shadcn 的 `data-state`（限定一组状态词，aria 已经表达的不重复）。这些是有限集合，读一次就够，**不随项目适配**——任意写法的视觉状态交给下面的样式核对
- **没写角色但能点的元素也发 ref**（tree.js `clickMarker`，复审 #8）：React/Vue 用 JS 绑定点击的 div/li、antd 下拉的可见选项，没写 role 但 `cursor:pointer` 或 `tabindex>=0` 的，交互快照和 find 都收，标 `[cursor=pointer]` / `[tabindex]`，名字取正文（info / 指纹同口径，「确定」这类名字照样命中有后果关键词闸门）。cursor 会继承：只认连续 pointer 链的最外层，选项的内容 span 不各占一个 ref。**读屏孪生体不进树**（`isA11yTwin`）：antd 另 render 一份 0 面积的 `role=option/listbox` 给读屏软件，屏幕上看不见、脚本点了也没用——快照里自己的行不发（子元素照常遍历，0 宽容器里溢出的可见弹出层不剪）、find 跳过。只认 option/listbox 这两个角色：别的自定义控件（slider/checkbox）可能只是没写样式才 0 面积，不能误杀；原生 `<option>`/`<select>` 除外（系统弹窗里显示，find 是选原生选项的唯一途径）
- **密码不进上下文**（tree.js `isSecret`）：`type=password`、autocomplete 为密码 / 一次性验证码 / 卡号 / 安全码的输入框，快照里只写 `[filled]`、不写值，`browser_type` 不回显；「显示密码」把 type 临时改成 text 的，见过一次是密码框就一直按密码框处理（`seenSecret`）。早先用户在面板里亲手输的密码以 `[value="…"]` 进快照，发给模型服务商、落进会话历史
- **快照里的值**：文本框、数字框、滑块（`aria-valuenow`）带 `[value=…]`；可编辑区只有最外层（编辑宿主）算输入框，正文前 50 字当值——里面的 `<p>` 以前各算一个无名 textbox、各占一个 ref。`role=textbox` 的 div 不能直接输入，明说而不是抛「Illegal invocation」。只给读屏软件的元素（绝对定位、1×1、内容裁掉，如组件库的 aria-live 播报区）不进树，可交互的照留
- **多标签**（page `Browser.tabs` / `current_id`，对齐 Playwright MCP / browser-use）：`Browser.view` / `page` / `console_sink` 指当前标签，桥的请求、模型的动作都作用于当前标签。页面要求开新窗口（`target=_blank`、`window.open`）走 `newWindowRequested`（不再覆写 `createWindow`——以前一律返回 None 拦下，B 站点视频卡片没反应）：用户发起的（`isUserInitiated`：真实点击，模型的点击现在也是真实鼠标事件）、或模型点击 / 输入后 1.5 秒内到达的（脚本点击退路下 `isUserInitiated` 是 False，按时间归因，`note_model_action`）开新标签并 `req.openIn(新 page)`（保留 window.opener，第三方登录弹窗靠它回传）；页面自己弹的（广告、定时弹窗）拦下、记控制台、面板闪一行；最多 10 个。后台打开（Ctrl+点击）不切换，其余切过去。关当前标签回到打开它的那个。工具：`browser_tabs(list|select|close)`、`browser_open(new_tab=True)`；点击 / 输入打开了新标签，结果说「打开了新标签 #N，已切换过去」并附新页面的交互快照（`_after_action`：动作后、算变化前后各查一次，新窗口请求是异步到的；开了新标签就不拿两个不同页面比变化）；不止一个标签时快照末尾提一句。ref 登记按 (标签, frame) 分开（每个文档的 ref 都从 e1 数起，不分开新标签的快照会把原标签的 ref 冲掉）；`browser_last_load` 带标签，切标签后另一个标签加载序号恰好相等不会误记浏览器检查。**面板每个网页一个标签**（key `lingxi:browser#<id>`，各自的 `BrowserView`：工具栏、开发者工具、错误页都按页），双向同步：用户点哪个网页标签，模型的当前标签就是它；模型开了新标签，面板多一个并切过去；模型切标签时用户正看着浏览器才跟着切。关一个面板标签只关那一页（最后一页等于关浏览器）；单独的 `BROWSER_KEY` 仍指「当前那个网页标签」，`close_file(BROWSER_KEY)` 关整个浏览器
- **点击是真实鼠标事件**（tools_browser `_press` → tree.js `pointOf` / `pointArrived` → bridge `mouse`）：顶层页面上，先滚到可见、算元素里的点击点，做命中检测（`elementFromPoint`，穿开放 shadow DOM），再往 view 的 focusProxy 直接发移动 + 按下 + 抬起（构造 `QMouseEvent` + `sendEvent`，按页面缩放换算坐标；**不用 `QTest.mouseMove`**——它会 `QCursor.setPos`，把用户正在用的鼠标拽到页面上，用户实测。直接发的事件 Qt 也不会「点哪焦点给哪」：用户 3 秒内在灵犀输入框里打过字（`page.note_user_typing`，主窗口的输入框按键里记）就不碰键盘焦点，否则照真点击那样交给网页），最后确认 pointerdown / click 真的落到了这个元素（`isTrusted` 的事件，捕获阶段记）。好处：靠 mousedown / pointerdown 打开的组件（antd Select、Radix 菜单）点得开——合成的 `el.click()` 只发一个 click，点不开还报「样式都没有变化」，模型可能去「修」用户的代码；被全屏遮罩盖住的按钮点不中，报「被挡住」并把挡在上面的东西放进围栏（真人也点不到，早先却能点中）；打开的新窗口在 Qt 看来是用户发起（多标签要靠它区分广告弹窗）。命中判定：落点在目标里、目标在落点里、或两者在同一个小组件里（往上 3 层内有共同祖先，不算 body / html——antd 的透明输入框上面叠着显示当前值的兄弟元素，真人点的就是那块；全屏遮罩和目标的共同祖先是 body，照样算挡住）。**iframe 里也发真实事件**（2026-11-24，网页小游戏实测：游戏整个在 iframe 里，会躲开鼠标的关闭按钮、拖拽都靠 pointerdown，脚本点击触发不了）：`_frame_offset` 算出 iframe 内容区在顶层视口里的位置——跨域 iframe 里拿不到 frameElement，只能从外层量：外层的 `__lx.frameBoxes` 列出各个 iframe 内容区（去掉边框、内边距）的位置和大小，按 Qt 那边这个 frame 的大小（bridge `frames` 给 `w` / `h`，尺寸相同的不止一个时再比地址）对上号，一层层加上去；iframe 有一截在外层视口外就先 `revealFrame` 滚进来。iframe 里的 `pointOf` / `pointArrived` 照常在 frame 里做，坐标加上偏移发给 view。退回脚本点击的情况：iframe 位置对不上号（尺寸相同又地址相同的不止一个）、原生 `<select>` 的选项（系统弹窗点不到）、元素没有大小、**面板没显示**（Chromium 不收输入事件，结果里说明「靠按下鼠标才打开的组件可能没反应」）。送达确认不到时不补点（可能点两次），只在结果里说明
- **「灵犀的鼠标」**（设计稿「浏览器：灵犀的鼠标」，`browser_panel._AgentOverlay`）：网页上面一层透明浮层（不接收鼠标、不改网页内容、截图不含它），画两样：模型操作中网页四周的靛蓝柔光（3px 实边 + 往里按距离连续衰减的光，按尺寸缓存成图，每 2 秒明暗呼吸，停手 1.5 秒后淡出；早先是给页面框留 2px 边距露出底色的细线，不显眼，而且每次开始 / 停下网页都要重新排版）；靛蓝指针 + 小标签，从上一个位置滑到这次的点（0.25 秒）、点击处一圈涟漪，输入时停在输入框右边「灵犀 · 输入中」，命中检测发现被挡住时变红「被挡住了」。事件来源：bridge `cursor_event(标签, x, y, 动作, 说明)`——真实点击由 `_mouse` 发，输入（`tree.js anchorOf`）和被挡住（`pointOf` 带回被挡的点）由工具层经 `cursor` 操作发；每个网页标签的视图只认自己标签的。状态卡跟着写上点 / 输入的是什么（「灵犀正在点击「添加」」，只给用户看）。设置 → 高级「显示灵犀的鼠标」（`agent_cursor`，默认开，立即生效）关掉只是不画指针，柔光照旧
- **ref 不进 DOM**：ref 只在隔离世界的 Map 里（`refs` / `elRefs`），截图前滚到元素走 `__lx.reveal`。早先写成 `data-lxref` 属性，存 innerHTML 的编辑器 / CMS 会把它存进用户数据
- **动作后的样式核对**（tree.js `watchPrepare` / `watchBaseline` / `watchReport`，tools_browser `_before_action` / `_style_text`）：文字树 diff 为空时，报**操作处附近元素实际计算样式**的前后差异（颜色、背景、删除线、透明度、显隐、阴影、transform、`::before/::after` 内容等），比如 antd 下拉选中只靠 class 上的背景色、只改颜色的「已完成」。设计目标是**不报假变化**（误判比漏报更糟：模型会以为点成功了），几道防线各有回归用例、用变异验证过（去掉任何一道对应用例就挂）：① 比的是计算样式不是 class 名，埋点 class、没写样式的状态 class 不报；② 我们自己的副作用（滚动到可见、聚焦）在记基线**之前**做完，Chromium 的焦点框和页面的焦点样式都不会混进来；③ 动作前空闲期就在自己变的元素（时钟、轮播，MutationObserver 记的）单独计数「没算进去」；④ 无限循环的 CSS 动画（加载转圈）动的属性跳过；⑤ 点击反馈闪一下又恢复的，比的是 settle 之后的终态，自然抵消；⑥ 边框 / 轮廓色跟着 currentColor 变的不重复报，子元素继承父元素的同样变化只报父元素；⑦ 聚焦 / 滚动带出来的**有限时长**过渡（bootstrap / antd 的焦点样式带 transition、滚到可见的淡入）要等跑完再记基线（`watchSettling` 报剩余时长，最多等 1 秒），等过了还在跑的标成「动作前就在变」。只靠后一层不够：那个元素上点击带来的真变化会被一起吞掉（有用例）。聚焦之后元素可能被页面改了（antd Tabs 往名字里插「Tab 1 of 3」），`_reconfirm_after_prepare` 重取指纹按新的执行，只有变成了有后果的动作才拒绝——早先第一次点击必被指纹拒掉。范围是「目标往上两层的整棵子树 + 祖先链 + aria-controls / label 指向」，最多 120 个元素；范围外的属性变化只给计数、明说「是否可见没核对」。都没变就明说「样式都没有变化」——这才是"确实没反应、别再点"的依据。两种情况不下这个结论：点击触发了导航、新页面还没到（`_navigation_started`：动作前后比导航序号 + 是否在加载，bridge `qturl` 带回 `loading` / `nav`），说「已开始导航」；面板从没显示过（过渡停在起点不走），说给不出结论。已知看不到：canvas、图表像素、范围外且没有属性变化的样式联动（交给截图）。**测试要让页面可见且有焦点**：offscreen 下不显示的话 visibilityState=hidden，焦点事件不触发、CSS 动画不走、定时器被节流，几个陷阱都不会发作，测了等于没测（变异实测过）
- **按键 `browser_press_key` / 拖拽 `browser_drag`**（2026-11-24，网页小游戏实测：那局的出口是 Esc、退出验证要把东西拖进框里，模型说「我这边没有键盘事件可发」）：按键走 bridge `key`——`page.parse_key` 认 KeyboardEvent.key 的写法（Escape / Enter / ArrowDown / Tab / 单个字符，Control+ / Shift+ 修饰；带 Ctrl / Alt / Meta 时不带文字），构造 `QKeyEvent` 按下 + 抬起发给 view 的 focusProxy（焦点规矩同鼠标）。给 ref 先 `focusRef` 把焦点交给它；只给 frame 时 `focusWindow` 把焦点交给那个 iframe。送达用 tree.js 捕获阶段的 `keydown` 确认（`keyWatch` / `keyArrived`，`isTrusted`），确认不到如实说「没确认送到……焦点可能在别处」，不说成按到了。回车可能提交：有元素按它的结构判（同 `browser_type` 的回车提交），没元素同「表单外回车即发送」——信任的本机来源不问，其余都问。拖拽走 bridge `drag`：移到起点、按下、分 12 步（每步隔 16ms 让页面处理 pointermove）移到终点、抬起；起点是 `pointOf`（滚到可见、命中检测），终点是 `to_ref` 的中心（`rectOf`，不滚动，要在可见区域）或起点加 dx / dy；iframe 里按 `_frame_offset` 换算，对不上号时直说拖不了。浏览器原生的 HTML5 拖放（draggable）走系统拖放循环，合成事件可能不响应（工具说明里写了）
- **坐标点击 `browser_click_at` + 截图报坐标**（2026-11-26，同一个网页小游戏：canvas 画出来的东西在文字树里没有 ref，完全点不了）：坐标是页面 CSS 像素（给 frame 时是那个 iframe 视口里的）。点之前 tree.js `describeAt` 看那一点上是什么（`hitAt`，不滚动、不做遮挡判定——落在谁身上就点谁），给它一个 ref、登记送达目标；落在 iframe 上时 `_frame_at_point` 按外层 `frameBoxes` + Qt frame 尺寸换算进那个 frame 再看一次（最多 4 层），对不上号直说点不了。**闸门按那一点的元素结构判**（落在提交按钮上照样每次问），来源按换算后的 frame；等确认卡期间那一点的元素变成了有后果的就拒绝。发真实点击后按 `pointArrived` 确认送达，确认不到如实说。结果里说点在了什么上（元素描述进围栏），那一点本来就可交互的提示下次直接用 ref。坐标从截图来：`browser_screenshot(locate=True)` 让识别模型用 `[x, y]` 报图片像素坐标，bridge `grab` 记下这张图左上角对应的页面坐标和每像素多少 CSS 像素（`cssX` / `cssY` / `cssPerPx`，缩放、裁剪、放大都算进去），工具层换算成页面坐标列在结果末尾（局部截图截的是 iframe 里的元素时再减掉 iframe 偏移、给 frame 视口里的坐标），报到图外的丢掉。**实测**（用户配的 deepseek-v4.1-flash，canvas 上两个圆，3 轮）：整屏截图报的位置离圆心 4.5–45px，6 次里 5 次落在圆里，整体往下偏；给 ref 只截 canvas 那一块后 5–11px、6 次全中；按整屏坐标点红圆 3 次都点中——不叠坐标网格，工具说明里让模型要点得准就给 ref 截局部
- **滚动 `browser_scroll`**：真实滚轮事件（bridge `wheel`：`QWheelEvent`）——滚动加载、虚拟列表、轮播常听 wheel，`scrollBy` 触发不了。实测 offscreen QtWebEngine 里 ScrollUpdate 相位的事件到不了页面，要用 NoScrollPhase；页面收到的 deltaY = −angleDelta.y / 2（pixelDelta 被忽略），所以滚 N 像素发 angleDelta = −2N。给 ref 滚那个容器（自己不能滚就找最近的可滚动祖先），不给滚页面 / 那个 iframe。落点（tree.js `scrollInfo`）要落在「滚的就是目标」的地方：中心可能压着嵌套的滚动区域（页面里的盒子、弹层），wheel 会滚那个区域——先试几个常见位置再按 5×5 网格扫，命中检测确认；**处处都压着别的滚动区域时改成直接设位置**（`scrollByPx`）并说明这次不会触发靠滚轮的加载（以前滚轮落到盒子上，页面纹丝不动）。滚完读位置核对（`_scroll_stable`：连续两次一样才算停，给真窗口里的平滑滚动用；offscreen 里滚轮是瞬时的，这一步在测试里测不出差别），位置没变时分清「已经到头」和「可能被页面拦了」。top / bottom 直接设位置（面板没显示也能做）；其余方向面板没显示时直说收不到滚轮事件。只读，不弹确认卡，Plan 模式可用
- **悬停 `browser_hover`**：`pointOf`（滚到可见 + 命中检测，被挡住照样报「被挡住」）后只发 MouseMove（bridge `mouse` 的 `move_only`，不按下、不碰键盘焦点），「灵犀的鼠标」移过去；tree.js 捕获 `pointerover` / `mouseover` 确认送达，确认不到如实说。settle 一下再算变化行 diff，新出现的菜单 / 提示框带着 ref（`_delta_text` 已经登记 diff 里的 ref），可直接点；触发点和菜单在同一块悬停区域里时点菜单项不会收起（测试守着）。只读，Plan 模式可用
- **等待 `browser_wait`**：text 等文字出现（gone=True 等消失，文字树 + 正文里找），ref 等元素消失（脱离页面、隐藏、换文档都算），都不给等页面安静下来（没有导航在途、文字树连续两次不变）；每 250ms 查一次，最多 60 秒。等的期间包在 `page.model_waiting()` 里（用户这时在网页上点出来的框归用户），每轮看 `state.stop_flag`，点停止马上停。超时不是失败：说清楚等了多久、看到的是什么，附这段时间的变化行 diff。只读，Plan 模式可用
- **H.264 / AAC 视频**（`browser/media.py`，2026-11-24 网页小游戏实测：mp4 广告一直「暂时没接通」，模型对着它反复点播放）：PySide6 自带的 QtWebEngine 不带专有编解码器（实测 canPlayType：H.264、AAC、HEVC 都不认，VP8 / VP9 / AV1 / Opus / MP3 认）。请求拦截器 `MediaInterceptor` 把**媒体类请求**里地址以 mp4 / m4v / mov / m4a / aac 结尾的改道到灵犀自己的 `lxmedia:` 协议（登记成安全协议 + 允许跨域，https 页面里不算混合内容；**要在任何 QtWebEngine 对象之前登记**，main.py 在 QApplication 之前调 `register_scheme`，`_get_profile` 再兜一次）；协议处理器 `MediaHandler` 在后台线程下载原文件（带页面地址做 Referer，300MB 以内）、用 imageio-ffmpeg 自带的 ffmpeg 转成 WebM（VP8 realtime + Opus），转好在主线程把文件交给页面（job 已经没了就算了）；按地址缓存在本进程的临时目录，退出时删。同一个文件同时被请求只转一次。**找 ffmpeg 不用 `imageio_ffmpeg.get_ffmpeg_exe()`**：它先跑一次 `ffmpeg -version` 验证、不给子进程 stdin，父进程没有有效标准句柄时（打包后的窗口程序、pytest 捕获输出）验证失败还缓存下来，直接到包里 binaries 目录找文件。管不到分段推流（MSE：B 站主站、YouTube 这类数据由页面脚本自己喂给解码器）；没装 imageio-ffmpeg 时不拦（和以前一样放不了）。打包：pyinstaller-hooks-contrib 自带 imageio_ffmpeg 的钩子，会把 ffmpeg 一起带上（安装包大约大 80MB）
- **ref 漏写 / 写错 frame**（`_ref_scope`）：一个标签里各个 frame 的 ref 是接着数的、不重号；没带 frame（或带错了）而这个 ref 恰好只在另一个 frame 里签发过，就按那个 frame 操作，结果里提醒「下次带上 frame=…」。以前报「ref 已失效：页面已换文档」，模型以为页面一直在刷新（一局里 4 次）。**闸门按真正的 frame 判来源**：先定 frame 再取 frame 的地址，顶层本机、iframe 公网时漏写 frame 也按公网问
- **截图 `browser_screenshot`**：`view.grab()`（bridge `grab` op，主线程）截可见区域，超过 1280 宽等比缩小，交给图片识别模型（复用 `models.describe_images_with_vision`，同 `read_image`），返回识别模型按 question 的文字回答而不是原图。**给 ref 只截那一块**（元素四周各留 40px，iframe 里按 `_frame_offset` 换算；bridge `grab` 的 `crop`，窄于 640 的放大到 3 倍、最多 960 宽）——整屏截图里的小字识别模型常读不出来。**提示词直接问问题**（`as_question=True`，不套 `read_image` 那段「只做识别、不要回答问题」的通用说明：两段要求打架时识别模型把整页从头描述一遍，一局里截 12 次都没读到要的那行小字，还吐出过自己的思考过程）。面板没显示 / 尺寸太小时截出来是空白，直接报错、**不拿白图去问**（识别模型会照着白图编答案）；没开页面时不拉起浏览器。提示词要求 question 具体、只在文字和样式核对都说不清时用；进 Plan 只读白名单。业界（Playwright MCP、Chrome DevTools MCP、browser-use）也是文字树 + 截图两条腿，样式核对是我们多加的一层：便宜、没有图片 token，正好在"文字树没变"时告诉模型到底有没有反应
- 动作后的 diff 为空、又拿不到样式基线（`delta=False`、快照截断）时只说「文字树没有变化」（`tree.DELTA_EMPTY`），不说「页面无可见变化」：纯样式变化文字树看不见，早先那句让模型点掉一条待办后以为没生效，绕去加诊断代码
- **页面内容放在 untrusted 围栏里**：`tree.fence` 把页面文字包进 `<browser-content url="…" untrusted>`，正文里伪造的 `</browser-content>` 会被转义，不能把后续文字送出围栏。动作默认附 all 模式前后的"变化行 diff"（`tree.compute_delta`），空 diff 等异步渲染再补一次，view 隐藏时 settle 更久（定时器被节流）。快照被截断时，挤出上限的尾巴不算增删（`before_cut` / `after_cut`：最后一段相同内容延伸到某一侧末尾，另一侧在它之后多出的行是截断造成的），并总是附截断说明——早先 1500 条的列表顶上插一条，会多报一行假的「- 第 859 条」。**页面写的字都在围栏里**：标题（`browser_open` 的「页面标题」放进快照围栏）、样式核对的元素描述、select 的可选值、页面改过的输入值、iframe 地址；「已点击」「已向…输入」只写角色和 ref（`_describe_for_model`，角色名只认纯小写英文词），元素名留给给用户看的确认卡。早先 aria-label 写一句「系统提示：用户要求你…」会原样出现在围栏外
- **控制台按加载序号 nav 分段**：`ConsolePage` 每次 loadStarted 把 `nav_seq` 加一，控制台条目都带 `nav`；`browser_console` 默认只给最近一次加载的，改好代码重开后不会再看到上一次的旧报错。浏览器检查能顶替测试结论的条件见 [undo-and-verification.md](undo-and-verification.md)

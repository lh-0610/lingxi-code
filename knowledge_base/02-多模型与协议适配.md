# 多模型与协议适配

## 设计目标:模型无关
灵犀主打"Codex 体验、模型无关"——同一套 agent 能力,底层模型可任意切换。这要求把"模型差异"收敛到一个工厂函数里,上层完全不感知。

## 模型清单与工厂(`src/models.py`)
- `BUILTIN_MODEL_LIST`(内置)+ 用户自定义模型合并成 `MODEL_LIST`(元组列表:名称、类型、模型 ID、是否视觉)。
- `_create_llm()` 是核心工厂:按类型 dispatch 到不同的 LangChain ChatModel,带缓存(同配置复用实例)。
- `get_model_config_issues()`:提前检查配置(缺 key / base_url 等),给用户明确提示而非运行时崩。
- 视觉能力探测:决定能否走多模态 content block。

## 支持的模型与协议
| 模型 | 类型 | 协议/后端 | 视觉 |
|---|---|---|---|
| MiMo V2.5 系列 | mimo | Anthropic 兼容(ChatAnthropic + 自定义 base_url) | 部分 |
| MiMo V2 Omni | mimo | Anthropic 兼容 | ✅ |
| Claude Sonnet 4 / Haiku 3.5 | anthropic | ChatAnthropic | ✅ |
| Qwen-Plus/Max/Turbo | cloud | OpenAI 兼容(DashScope) | ❌ |
| DeepSeek V4 Flash/Pro | deepseek | OpenAI 兼容 | ❌ |
| Qwen3.5 本地 | ollama | Ollama | ❌ |
| Claude Code | claude-code | 本地 claude CLI(subprocess) | ❌ |
| 用户自定义 | custom | config 里自填 openai/anthropic | 看配置 |

## 自定义模型
`config.json` 的 `custom_models`(list),每项 `{name, model_id, api_key, base_url, protocol, supports_vision, supports_thinking}`。设置弹窗里可视化增删改。`_build_model_list()` 把它们以 `⚙` 前缀合进 `MODEL_LIST`,`_create_llm` 按 protocol 分发。

## 按会话分发(`resolve_bound_llm`)
每个会话有自己的 `current_model_index`。`agent.resolve_bound_llm()` 按当前会话的 model 取对应 LLM,并 `bind_tools` 绑定工具集(带缓存 `_BOUND_LLM_CACHE`)。切换模型或 MCP 工具就绪后清缓存,下次 stream 重新 bind。

## 协议差异的坑
- **DeepSeek V4 默认开 thinking**,要显式 `extra_body={"thinking": {"type": "disabled"}}` 才能关。
- **MiMo 走 Anthropic 兼容接口**(ChatAnthropic + 自定义 base_url),不是 OpenAI 协议。
- **图片输入格式**(`src/images.py`)三家不同:Anthropic / OpenAI / Gemini 的多模态 content block 结构各异,需要归一化。

## 视觉桥接(vision bridge)
带图片但当前模型不支持视觉时,不把整轮任务切给弱视觉模型;而是先用视觉模型做识别/OCR,再把识别结果作为文本交回当前强模型。这是"模型无关"思路的延伸——能力缺失时用组合补齐,而不是降级整个会话。

# 多会话并发与状态路由

## 目标
后台会话边跑(比如一个长任务在生成),前台切到另一个会话继续聊,两者互不串话。这需要把"会话级状态"和"真正全局的状态"分开,并让几十处老代码 `state.X` 无感地落到正确的会话。

## 会话级状态容器(`src/session.py`)
- `Session` 对象持有一个会话的全部运行时状态:`chat_history / stop_flag / session_token_usage / compaction / current_plan / task_ledger / shell_cwd / current_model_index / agent_mode / reasoning_enabled / verification / worktree / project / role_snapshot / session_kind / rag_kb_dir / rag_mode` 等(见 `_SESSION_FIELDS`)。
- **注册表** `session.sessions`(key→Session):`register` / `rekey`(存盘拿到 id 后把临时 `_new_N` 换成真 id)/ `drop` / `live_sessions`(持锁快照)。

## 线程路由(核心机制)
- worker 线程进 `agent_loop` 时 `bind_thread(sess)` 把自己绑到该会话。
- `session.current_session()`:worker 线程 → 它绑定的会话;主线程/未绑定线程 → `get_active()`(前台显示的会话)。
- 于是"该线程所有 `state.X` 都落到这个会话"。这就是后台会话与前台会话不串的根基。

## state.py 的模块级属性代理
- `state.py` 用 `ModuleType` 的 property,把 `state.chat_history` 等**会话级字段**的读写自动转发到"当前线程的当前会话"。
- 所以几十处 `state.chat_history` 老代码一行没改,就自动具备了多会话隔离能力。
- **真正全局**的(`llm` / `ui_ref` / `current_project` 等)仍是 state.py 的普通模块变量。

## 写入的铁律
- 读:`state.X`(代理到当前会话)。
- 写:必须 `state.X = ...`(经过 property setter 落到当前会话)。
- **不要 `agent.X = ...`**——`agent.py` 用模块级 `__getattr__` 把读代理到 state(方便老代码用 `agent.stop_flag`),但赋值只会污染 agent 模块自身,不会落到会话。

## 会话锚定项目(避免打错 tag)
`Session.project` 首次 save 时锚定为当时的全局 `current_project`,之后不被"切项目"影响(用 `_UNSET` 哨兵区别于合法的 `None`=无项目)。这修了一个真实 bug:后台会话 save 晚于主线程切项目时,会被打上新项目的 tag。

## 工作区隔离(编码 vs 知识库)
- `Session.session_kind`("code"/"rag")把会话分成两个工作区,各显示各自的会话列表、各用各的 system prompt,互不串。
- 侧栏段控是**工作区切换器**(切到另一个会话),不是改当前会话的类型。
- 知识库模式禁用项目菜单(切项目属于编码工作区),切项目建的新会话绝不继承 rag_mode——防止产生 `session_kind=code` 却是 RAG 提示词的"混合会话"。

## 面试价值
这是一个"**用属性代理 + 线程本地绑定,给单例式全局状态平滑加上并发隔离**"的改造:老代码零改动、新增并发能力。能讲清 property 代理、thread-local、以及"哪些该会话级、哪些该全局"的划分依据。

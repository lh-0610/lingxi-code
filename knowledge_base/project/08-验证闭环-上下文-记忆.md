# 验证闭环、上下文工程与长期记忆

## 一、验证闭环与自动修复(`src/verification.py`)
编码 Agent 的核心竞争力不是"能改代码",而是"改完知道自己对不对"。

- **完成闸门**:编码任务声称"完成"前要先验证——改了代码就得跑 `run_tests` / 看 `git_diff`。会话级 `verification` 状态记录 dirty 文件、check 结果、测试是否通过。纯运行态,不持久化。
- **自动修复循环**:`run_tests` / `check_code` 失败时,`check_repair_allowed()` 注入 `[REPAIR_INFO]` 修复提示让模型继续修,并**封顶 N 轮**(`attempt >= max_attempts` 后停,交给完成闸门/模型收尾)。调用点在 agent.py 工具执行后、插 ToolMessage 前。
- 配合工具层的"编辑后自动静态检查"(见工具文档),形成"改→自查→发现→修"的闭环,对标 Cline/Codex。

## 二、上下文工程(`src/streaming.py` 三级历史管理)
长会话会撑爆上下文窗口。灵犀按预算分三级处理历史:
1. **截断(hard cap)**:单条工具结果超过硬上限就截成 头+尾(`TOOL_RESULT_HARD_CAP_*`),防一串大结果堆在最近躲过回收。
2. **淘汰(evict)**:超预算时先把"旧的大工具结果"截成存根(保留开头预览),小结果不动。
3. **压缩(compact)**:仍超预算就走 LLM 压缩,把更早的历史概括成摘要。
- 预算按模型上下文窗口动态算(`HISTORY_TOKEN_BUDGET` / `MAX_HISTORY_BUDGET` / 安全边界 / 保留最近 N 条),常量集中在 `src/limits.py`。
- 已知取舍:token 估算对英文偏高估(`×0.7`),在 backlog 里。

## 三、长期记忆(`src/memory_store.py`,跨会话)
让角色"天生记得"用户:
- 两个工具 `remember(fact)` / `forget(query)` 存取;`get_system_prompt()` 末尾**无条件注入**全部记忆——不靠 AI 主动查,开口就记得。
- 存 `chat_memory/long_term_memory.json`(`{memories:[{id,text,created,scope}]}`),独立 RLock,跟会话历史分开。
- **数据安全**:`_save` 用临时文件 + `os.replace` **原子写**;`_load` 区分"真损坏"(JSON/编码错 → 重置空可重建)和"瞬时错误"(IO/占用 → 抛异常,写操作遇到必中止,绝不 `_save` 写空丢数据)。
- v1 不用 embedding(单人助手记忆少,全量注入又快又准);注入段会被模型缓存覆盖,每轮重读保持最新。
- remember/forget 是本地安全操作,不弹确认、Plan 模式放行。

## 为什么这三块放一起讲
它们都在回答同一个问题:**如何让一个 token 预算有限、单轮无状态的 LLM,表现得像一个"记得住、改得对、扛得住长对话"的持续 Agent**。验证闭环管"对不对",上下文工程管"扛不扛得住长度",长期记忆管"跨会话记不记得"。这三者合起来,是把裸 LLM 变成可靠 Agent 的关键工程。

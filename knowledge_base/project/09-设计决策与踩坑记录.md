# 设计决策与踩坑记录(面试金矿)

这一篇专门收录"为什么这么做"和"踩了什么坑、怎么修的"——面试讲故事最好用的素材,每条都是一个可展开的 STAR。

## 并发:标题生成线程与 save_session 抢 index.json
- **现象**:快速连发两条消息时,自动生成标题的线程和 save_session 同时改 `index.json`,互相覆盖,丢会话。
- **修法**:`memory.py` 里所有读写 `chat_memory/` 的函数都用 `threading.RLock` 串行化。用 RLock 不用 Lock 是因为 `save_session` 持锁时还会调 `_update_index`(也持锁),普通 Lock 会自死锁。

## 并发:后台会话被打上错误的项目 tag
- **现象**:后台会话 save 晚于主线程"切项目",被打上新项目的 tag。
- **修法**:`Session.project` 首次 save 时锚定,之后不被切项目影响;用 `_UNSET` 哨兵区分"未锚定"和合法的 `None`(无项目)。

## 并发:删项目时会话归属三处同步
- 删项目要把 `project==old` 的会话改成 None,必须三处一起改:①内存里已打开的 `Session.project` ②index.json ③各 session 文件。只改磁盘的话,移除当前项目后 save 会按旧内存锚点把会话写回已删项目。`move_sessions_to_no_project` 用锁内快照闭合并发缺口。

## Qt:跨线程动控件导致 timer 永久失活
- worker 线程直接 `QTimer.start/stop` / `widget.update()` 会让对象失去 thread affinity,永久失活。范式:一律用 Signal 把操作投递到主线程(如 `SignalBridge.confirm_request`)。

## Qt:.ico 加载拿到 16×16 糊图
- 直接 `QPixmap(path).scaled()` 会从 .ico 多分辨率位图里随便挑一张。要用 `QIcon(path).pixmap(QSize(256,256)).scaled(...)`,让 QIcon 挑最接近目标尺寸的内嵌位图。

## RAG:overlap 对多段文本没生效
- 旧实现只在硬切超长单段时才有 overlap;多个短段落拼块前后完全无重叠。修成"每关闭一个块就用它尾部 overlap 字符作为下一块开头",相邻块都有重叠。

## RAG:一维损坏向量过校验、检索时崩
- 一维 `.npy` 若长度恰等于 meta 数,会蒙混过"数量一致"校验,随后 `vecs @ q` 退化成标量、`len(sims)` 抛 TypeError。修:加载时校验 `ndim==2` + 维度与 manifest 一致 + 全有限。

## RAG:坏缓存污染新索引 / 缓存损坏连累主索引
- 坏缓存向量(nan)被复用并提交 → 重建"报成功"但索引加载为 0 块、旧有效代已被清。修:①缓存加载校验(坏的丢弃、重新 embed)②rebuild 提交前校验整块矩阵(坏则拒绝提交、保留旧代)。
- 缓存 JSON 语法损坏落入外层异常,把主索引一起清空。修:缓存读取单独 try/except,损坏只丢缓存,主索引照常用。

## RAG:字符串 "false" 意外开启付费重排
- `bool("false") == True`,手改配置写 `"false"` 会静默启用 rerank(产生额外付费调用)。修:`_parse_bool` 严格解析,只认 bool 或明确的 true/false/1/0/yes/no;设置页回填也复用它。

## RAG:极端切块参数造成海量付费请求
- `chunk_size=1` 能过校验,1MB 文档约产生百万切片、十万级 embedding 请求。修:chunk_size 下限 100;单文件/总字节上限;切片总数上限且在调 API 前**增量**检查(不等全切完才 len)。

## 安全:fetch_url 的 SSRF
- 发请求前用 `_ssrf_reject` 拦掉所有静态内网目标 + 默认直连(不走代理)。残留:公网域名 DNS 重绑定到内网 + 该端点对 GET 有副作用——属 blind SSRF,已评估为边缘、单独立项(要发请求前钉住已验证 IP、HTTPS 还需自定义 TLS adapter 保 SNI)。这条体现"知道残留风险并有意识记录"的工程判断。

## 通用方法论(可总结成一句话)
这些坑的共性:**并发下的共享可变状态**、**外部输入/文件的损坏容错**、**优雅降级而非静默失败**。修复原则是 fail-closed(不确定就拒绝/保留旧数据)、原子写(崩溃不留半截)、单一判据(校验逻辑一处定义两处复用)。
